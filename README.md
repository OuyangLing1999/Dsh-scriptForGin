# 剧本工作台

面向 DeepSeek Harness（DSH）的编导辅助插件，为 60 岁以上观众的连麦直播与家庭伦理短视频提供选题、结构、对白、改编、审稿和返修支持。使用者是有基础的编导，创作判断、事实确认和版本采用由编导控制。

当前工作区版本为 **2.9.0**。

## 上手引导

首次打开显示「带稿工作 / 从零创作 / 先看一个示例项目」三选一，可跳过、可在「工作台设置」重新打开。示例项目含完整选题、人物卡、成稿与审稿记录，用于理解四个分区和候选稿 / 已采用稿 / 审稿记录的关系。

## 安装与升级

在 DSH Web GUI 的插件管理中安装本目录，或将安装 ZIP 解压后安装解压目录。宿主端内置 Zod，安装包无需额外安装依赖。首次安装或升级后重新加载插件并刷新页面，以加载新的客户端及结果投影。

升级前可从「工作台设置」导出项目备份。项目保存在当前浏览器，清理网站数据或更换浏览器前请备份。

## 带稿工作

1. 打开侧边栏「剧本工具」，在「创作简报」填写或导入原稿。
2. 选择直播创作、直播优化、视频扒片或短视频改编；选择思路、大纲或完整剧本，直接执行。
3. 在「稿件工作区」浏览结果。修改意图、按话轮 / 场次限定范围或选中文字后返修，都会保存新版本。
4. 思路与大纲可以反复优化、润色，再扩展为后续稿件；编辑也会保留内容类型。
5. 点击「采用此稿」设置默认工作稿。生成新候选稿不会替换已采用稿。
6. 导出 Word，或在「更多」中导出 Markdown / TXT、提取人物卡、收入样稿库。

## 管理简报、素材和参考

- **创作约束**：人物关系、冲突、角色诉求、结尾、锁定事实和保护台词。
- **结构资料**：可编辑已确认大纲与结构指纹，用于后续生成。
- **素材收件箱**：TXT、Markdown、字幕、DOCX 读取后先预览，再选择保存为独立素材、追加或替换。多文件不会逐个覆盖原稿。独立素材需主动追加至原稿后参与创作。
- **视频 / 音频**：选择后在提交时上传；文件本体不存入浏览器项目，刷新或切换项目前先提交。也可提供 DSH 所在电脑可访问的路径。
- **人物与样稿**：维护主播人设、人物卡和已选样稿。AI 人物提取先保存草稿，由编导勾选合并。

## 审稿、检查与版本

AI 审稿及人物提取原文单独存入「审稿记录」，关联来源版本。可将意见带回来源稿再返修，报告不会进入正文版本。结果区提供「按最新意见返修」，一键把审稿意见填入修改意图。

完整剧本显示**角色台词统计**：直播稿按角色行、短视频按台词说话人，展示段数、字数与占比。稿件支持**全文搜索**、命中计数、上一个 / 下一个跳转与高亮。

完整剧本会运行程序格式检查；润色结果会显示预设表达自检。检查提示提供定位与返修入口，事实和创作质量由编导复核。自动返修为可选项，开启后最多追加一次 AI 调用。

长稿版本对照先保留共同前后缀，在预算内精确比较；更大中段采用有界窗口，界面明确标注「近似比较」。

任务切换到后台项目后继续接收结果。新任务保存提交文本与来源快照，失败后可按原输入重试；旧任务缺少快照时会明确提示按当前资料重新提交。导入备份或生成冲突副本会重置任务与会话关联，素材和稿件保留。

## 工作台设置

可切换统一字号、导入导出备份、选择关联会话和检查更新。打开面板时检查 GitHub 正式版，保持打开时每 30 分钟重查。

当前发布形式为 ZIP，需下载、解压并通过插件管理安装。插件会识别本地安装来源，避免把重新安装旧目录误报为升级成功。只有宿主明确支持且来源、版本均核验通过的官方远程 TGZ/TAR.GZ 资源才使用远程安装。

## 开发与验证

```bash
npm run build
npm test
node --check client.js
node scripts/browser-check.mjs
node scripts/workbench-browser-check.mjs
```

真实 GUI 检查支持 `DSH_WEB_URL`；默认地址为 `http://127.0.0.1:11567`。新浏览器没有登录状态时会记录认证阻碍，不把认证页视为插件验证成功。

独立浏览器测试使用真实构建后的客户端、宿主 React 与模拟 DSH 会话，验证阶段流转、稿件归档、导入和响应式布局；它与真实 GUI 集成验证分别记录在 `artifacts/browser-check/`。

源码入口：`client-ui.js`、`workbench.css`、`workbench-model.js`、`workbench-core.js`、`result-projection.js`。`client.js` 和 `index.js` 由构建生成。

发布脚本包含提交、推送和 GitHub Release 操作，仅在明确要求发布时运行。只做发布前检查可使用 `node scripts/release.mjs --check`。
