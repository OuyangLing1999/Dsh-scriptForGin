# 工作模式与输入输出

## 扒片模式

输入为可读取视频，以及可选的人名、账号背景、连续剧情状态、时长或拍摄限制。先用原生视听联合分析建立证据表，再提取结构指纹，最后直接生成完整母版，不另交付一份冗余“事实还原稿”。

### 证据表

按时间顺序记录可见/可听事实：人物、位置、动作、表情、台词要义、字幕、声音、停顿、镜头变化和空间开闭。区分：

- 明确：画面与声音共同支持，可写成确定内容。
- 可合理概括：不改变事实的口语化归纳。
- 不确定但影响拍摄：关键事实先向用户确认；只能现场决定的非关键项填写实际负责人和时点，例如 `【待现场确认：责任人=现场制片；时点=开拍前】`，不得补全事实或保留模板占位词。
- 不影响因果的小口误、语气词：无需工具复核。

### 证据状态不可升级

对病历、照片、鉴定、聊天记录、现金、合同等关键材料，先标明原片状态：`提及 → 承诺提供 → 实物在场 → 当场出示 → 已经核验`。后一级必须有原片画面或声音支持；成稿的准备清单、人物动作、台词、花字和爆点只能保持原状态，不能自行向后升级。

- 原片只说“可以拿来、下次带、愿意提供”，状态是**承诺提供**：只保留口头承诺，不把材料加入本集道具清单，不写掏出、递交、展示或他人查看。
- 原片只拍到材料在场但没有打开，状态是**实物在场**：可以写持有人和位置，不能写内容已被看见或确认。
- 原片有人查看材料但没有得出结论，状态是**当场出示**：可以写查看动作，不能写已经核验。
- 只有原片明确完成核验并给出结果，才能写**已经核验**；仍要区分角色说法与客观结论。

### 结构指纹

必须单独保存来源实际具备的开场功能、单集任务、人物/演示者职责、空间路径、信息或步骤递进、证据、阶段收获与结尾。家庭剧情另记核心关系、诉求、门槛、阻力、阵营、情绪兑现与追更债务；无对应内容的项记“不适用”，不为知识、幽默、退休或旅行内容补造家庭冲突。项目受众、题材和风格作为改编方向，原片证据与编导明确要求优先。

### 输出

写入：

```text
短视频剧本项目/<视频文件名>/
├── 母版拍摄稿.md
└── 结构指纹.md
```

母版遵守 [最终拍摄稿模板](最终拍摄稿模板.md)，粒度足以让导演、演员、摄影和剪辑不回看原片也能执行；可执行性不能以新增原片没有的证据、道具或动作换取。

## 改编模式

输入为已保存或用户明确指定的母版、对应结构指纹，以及人物、关系、题材、场景、道具、预算、时长等新要求。找不到可识别母版时要求用户指定。

先生成改编对照：`母版结构项 → 新故事实现 → 是否锁定 → 冲突/补偿`。再按 [高保真改编规则](高保真改编规则.md) 写完整新稿，不能把结构对照当成最终拍摄稿。

写入同一项目：

```text
├── 改编要求.md
└── 改编拍摄稿-v1.md  # 后续递增 v2、v3
```

## 冲突处理

- 要求与母版结构冲突：明确指出冲突，采用最接近母版机制且满足用户核心意图的实现，并说明补偿；不得静默破坏结构。
- 多项要求互相矛盾：若无不改变核心意图的唯一解，列出冲突并请用户选择。
- 连续剧情资料冲突：以用户最新明确事实为准，保留变更记录；研究编号、文件顺序和推测不得冒充剧内顺序。
- 视频读取失败：报告失败并按工具条件尝试；仍无法获得可靠证据则停止，不生成想象剧情。

## 完成定义

两种模式都必须输出八段式完整拍摄稿、顶层 `登场人物/空间路径` 声明、逐场 `位置/出场人物/空间动作` 等完整字段、明确时长预算并通过交付前校验。所有逐场人物必须来自顶层声明；第一场从空间路径起点开始，后续位置只能停留或走到下一节点，不得跨级或跳到路径外；离场回到旧地点时必须把该地点再次列入完整行程。仍含 `【待现场确认】` 的关键项必须先向用户确认；确实只能现场决定的非关键执行项必须填写实际负责人和确认时点，不得保留“姓名、某人、待定”等模板占位词。
